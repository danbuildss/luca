# Luca Roadmap

## Phase 1 — Private financial employee (NOW)

- hermes installed on mac
- luca identity files in place
- bankr agent api as llm
- telegram bot connected
- connect wallet
- read balances
- read transactions
- classify transactions
- remember corrections
- produce reports
- investigate transactions

## Phase 2 — Continuous monitoring

- scheduled wallet checks via hermes cron
- daily briefs via telegram
- material alerts only
- treasury monitoring
- spending anomaly detection
- counterparty tracking

## Phase 3 — Better financial intelligence

- recurring revenue detection
- recurring expense detection
- runway calculation
- cash-flow analysis
- financial trends
- x402 economics
- agent economics

## Phase 4 — Private user expansion

- onboard 2–5 private users
- isolated memory per user
- per-user wallet sets
- per-user corrections
- no public access

## Phase 5 — Developer infrastructure

- Luca API
- MCP interface
- programmable financial intelligence
- agent-readable reports
- wallet intelligence endpoints

## Phase 6 — VPS migration

- move hermes runtime from mac to vps
- postgres for structured ledger
- 24/7 uptime
- proper backups
- monitoring

## Phase 7 — Controlled execution

Only after:

- security architecture
- explicit permissions
- transaction previews
- spending limits
- policy engine
- human approval
- audit logs

Execution must never be the starting point.

---

## Success Criteria

Luca succeeds when:

A principal can attach their wallets and stop manually checking explorers to understand their financial operations.

The principal should trust Luca to:

- know what happened
- remember why it happened
- notice important changes
- explain the financial position
